## Что сделано (рецепт → рэймарчер)

| Слой рецепта | Как сделано в игре |
|---|---|
| 1. Низкое внутреннее разрешение + nearest | canvas = 120/180/240 строк (+ поле 1 px со всех сторон), растягивается CSS `image-rendering: pixelated`. HUD — отдельный canvas `#ov` и DOM — остаётся чётким. Авто: Денди 180, 16-бит 240 строк. |
| 2. Текстуры без сглаживания | у рэймарчера процедурные материалы — «пикселит» само низкое разрешение; фильтров текстур нет. |
| 3. Свет в 3 ступени | `scene.glsl`, юниформ `uDen` (vec4): солнце — тень / полутон / свет, точечные источники — 4 ступени, жёсткий блик, добавка рассеянного в тени. |
| 4. Обводка 1 px | финальный проход: вторая разность **обратной** глубины (1/z линейна по экрану у плоскости → нет ложных линий на дальней земле). Глубина рэймарчера уже есть (`gl_FragDepth`, логарифмическая), нормали не нужны. Силуэт ×0.3, сгиб ×0.68; гаснет 160→300 м. 3D-оружие в руках чистит буфер глубины — его глубина пишется в отдельную текстуру. Окно живого портрета (стратегия) без обводки. |
| 5. Палитра + Байер 4×4 | NES 54 цвета (взвешенное расстояние 0.35/0.5/0.25) или 3 бита на канал (512). Перед палитрой — гамма/насыщенность/яркость (`DEN75.gain`), иначе приглушённая картинка игры уходит в серый. Дизеринг гаснет 70→220 м (небо и даль — ровными пятнами). Зерно плёнки и VHS-шум в Денди выключены (`uDen` в `post.glsl`), иначе пиксели палитры мерцают. |
| 6. Рубленая анимация | `floor(t*fps)/fps` (6/12 к/с): время шейдера (вращение, мигание, пламя, сияние), фаза шага бойцов (OBJ[15]), скелетные позы тяжёлых (HV65), огонь/дым/обломки/пыль (позиция и возраст держатся до следующего «денди-кадра»). Камера, управление, симуляция, снаряды — плавные. |

Меню: ПК — Настройки → Графика → «Стиль графики: Обычный / Денди (8-бит) / 16-бит (512 цветов)»; при не-обычном стиле — строка «Расширенные…» с кнопкой ⚙: размер пикселя (авто/120/180/240), рубленая анимация (выкл/6/12), обводка, дизеринг, привязка камеры. Телефон — ☰ → Настройки → Графика, те же пункты кнопками − / +. Подписи RU/EN/VI/HE через `tr()`. Адресная строка: `?dendy=1|2&rows=120`.

## Хуки в чужом коде (минимум)

- `scene.glsl`: `uniform vec4 uDen;` + 3 ветки `if (uDen.x > 0.5)` в `pointLights()` и `shade()` (обычный код не изменён, ветка — поправка поверх).
- `post.glsl`: `uniform float uDen;` + два `if (uDen < 0.5)` у зерна плёнки и общего шума.
- `build.py`: одна строка `JS.insert(JS.index('main.js'), 'v75_dendy.js')` перед циклом сборки.
- **`render.js` не изменён.** Всё остальное — обёртки в `v75_dendy.js`: `resize`, `render`, `gatherObjects`, `gatherParticles`, `applySettings`, `MENU.load`, `MENU.html_settings`, `HV65.animate`, `WPN69.draw`, `CAM66.glRect`, `P71M.CH/sec`; `SCENE_U/POST_U.push('uDen')`.
- При стиле «Обычный» каждая обёртка сразу зовёт оригинал, `uDen = 0` (по умолчанию GL) — см. A/B ниже.

## FPS / стоимость кадра

Внимание: 2080 Ti сейчас не определяется Windows, все замеры — на **Intel UHD 630**; параллельно на том же GPU работали два чужих headless-Chrome (chrome_v75, chrome_v75a), поэтому абсолютные цифры завышены постоянной задержкой ~150–250 мс; смотреть на соотношение.
Метод (`tests\v75d_gpu.js`): время `render()` + `readPixels` (синхронизация GPU), медиана из 3 кругов, режимы попеременно.

| то же — стратегия | 638 мс | 245 мс (×2.6) | 174 мс | 277 мс |

| то же — стратегия | 511 мс | 261 мс | 256 мс | 411 мс |
| Телефон 844×390, лёгкий режим (464×215) — шутер | 196 мс | 184 мс | 127 мс (×1.5) | 210 мс |
| то же — стратегия | 237 мс | 185 мс | 163 мс | 255 мс |

rAF-FPS (`tests\v75d_bench.js`, ПК высокое): обычный 1.7–2.8, денди-180 1.1–1.3, денди-120 3.6–4.2, 16-бит 3.5–6.3 к/с — при 1–6 к/с и чужой нагрузке на GPU это шум; надёжнее таблица выше. Сам проход Денди (обводка+палитра) — 0.01–0.02 мс CPU, на GPU — один полноэкранный проход по 60–70 тыс. пикселей.
Вывод: на ПК Денди даёт до ~5×; на телефоне выигрыш есть только при 120 строках (лёгкий режим и так рисует мало пикселей). Для автоопределения «Денди по умолчанию на слабых телефонах»: естественная точка — `LITE73.adapt(fps)` (когда масштаб уже минимальный, а FPS < ~20 — предложить/включить Денди 120). Не сделано — по заданию по умолчанию «Обычный».

## «Ползающие пиксели» (п. 5)

Сделано: поворот камеры квантуется на целые «денди-пиксели» относительно опорной камеры (базис — от опоры), остаток < 1 px — плавным сдвигом canvas в CSS (поля по 1 px). Опора сбрасывается при крене снимка > 0.004 рад (на шаре «верх» меняется при ходьбе; у наклонной камеры — при повороте), при повороте > ~25°.
Замер (`tests\v75d_crawl.js`, поворот по 0.1 px/кадр, доля изменившихся пикселей после компенсации целого сдвига):
- 180 строк: с привязкой медиана 0.37%, 10/39 кадров без изменений; без привязки 1.07%, 0/39;
- 120 строк: с привязкой 0.15%, 27/39; без привязки 1.29%, 0/39.
Не лечится: перемещение камеры (ходьба, полёт, ранец) — перспектива пересчитывает сетку; в моменты смены опоры — один «скачок» кадра. Выключается галкой «Привязка камеры к пикселям».

## Ограничения

- 3D-модели (тяжёлые бойцы HV65, оружие WPN69, постройки ST70) — свои шейдеры: свет у них не ступенчатый; палитра, обводка, низкое разрешение и рубленые позы работают.
- Кино/оператор (`S.fixedRes`) — Денди выключается (запись видео всегда в обычном стиле).
- Искажения (ударная волна) работают в низком разрешении — выглядят «крупно», это в стиле.
- Дальние скалы с обводкой дают рябь — поэтому обводка гаснет после 160–300 м (`DEN75.fade`).
- Тонкая настройка цвета в коде: `DEN75.gain` (Денди), `DEN75.gain16`, `DEN75.lit` (ступени света), `DEN75.tol` (обводка), `DEN75.dith`.
